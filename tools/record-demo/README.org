#+title: Recording the lambdock showcase GIF
#+author: lambdock contributors
#+options: toc:nil num:nil

This directory contains a reproducible end-to-end recorder for the lambdock
demo GIF.  One command starts a *nested niri session* inside your current
session, runs lambdock there, drives the dock through a scripted storyboard,
records the nested output with =wf-recorder=, and encodes a framed,
palette-optimised GIF.

#+begin_src sh
meson setup build && meson compile -C build
./tools/record-demo/record-demo.sh
# writes resources/img/lambdock-demo.gif
#+end_src

The result shows every headline feature and every built-in theme:

- a title card, then auto-hide once (reveal at the edge, slide away),
- native fish-eye magnification (a slow pass across the dock),
- launching applications, with running indicators,
- the window popover HUD and *Close All*,
- the dock's own right-click menu, then the Preferences window,
- a folder stack browsed as a thumbnail grid,
- the launchpad filtered from the REPL,
- live mutation through the Guile socket REPL (icon size, then themes),
- hot-swapping the built-in dark and light themes,
- taskbar mode, and a closing title card.

** Options

#+begin_src sh
./tools/record-demo/record-demo.sh --keep            # keep raw.mkv + events.tsv
./tools/record-demo/record-demo.sh --width 1200      # bigger GIF, same story
./tools/record-demo/record-demo.sh --fps 24          # smoother (bigger) GIF
./tools/record-demo/record-demo.sh --capture-width 1728
./tools/record-demo/record-demo.sh --keep-cursor     # never touch the host config
./tools/record-demo/record-demo.sh --build
./tools/record-demo/encode-demo.sh --raw raw.mkv --events events.tsv --out demo.gif
#+end_src

=tools/record-demo/out/lambdock-demo.gif= is the default output and is ignored
by git; the copy that ships lives in =resources/img/=.

Recording and encoding are deliberately two programs.  Re-encoding is cheap and
needs no compositor, so tuning the frame, the captions or the palette works on
a recording you already have:

#+begin_src sh
./tools/record-demo/encode-demo.sh \
    --raw /tmp/lambdock-demo.XXXX/raw.mkv \
    --events /tmp/lambdock-demo.XXXX/events.tsv \
    --out /tmp/look.gif --keep
#+end_src

* Requirements

The recorder must run *inside a running niri session* (it uses =niri msg= and
spawns a nested niri).  It refuses to start otherwise.

| Thing                        | Why                                                        |
|------------------------------+------------------------------------------------------------|
| =niri=                       | outer + nested compositor, window actions, output geometry |
| wlr-virtual-pointer support  | pointer motion, buttons and scroll for the storyboard      |
| =wf-recorder=                | screen capture of the nested output                        |
| =ffmpeg= with =libass=       | captions, palette generation, GIF encoding                 |
| =gifsicle=                   | final lossless optimisation of the GIF                     |
| =wayland-scanner=            | generates the virtual-pointer protocol bindings            |
| =gcc=, =pkg-config=          | builds the tiny =vptr= helper                              |
| =python3= + =numpy=, =Pillow= | wallpapers, framing, captions, storyboard                 |
| =kitty=                      | the terminal that hosts the live REPL demo                 |
| =alacritty=                  | the application the dock launches                          |
| =fastfetch=                  | content for the demo terminals (optional, skipped if absent) |
| =swaybg=                     | wallpaper rendering inside the nested session              |
| =dbus-run-session=, =setsid= | private session bus and process-group cleanup              |
| =jq=                         | parses =niri msg -j= output                                |
| =Noto Sans=                  | the caption font                                           |

Also required: =wayland-client= development files (=pkg-config
wayland-client=).  The script checks all of this up front and exits with a
clear message if something is missing.

* How it works

** Isolation

The nested niri runs with a temporary =HOME=, =XDG_CONFIG_HOME=,
=XDG_DATA_HOME=, =XDG_CACHE_HOME= *and =XDG_STATE_HOME=*, under
=dbus-run-session=, so the host lambdock instance, its single-instance lock and
its =layout-/preferences-settings.scm= files are never touched (forgetting the
state dir made the demo dock read the developer's own overrides).  A generated
=settings.scm= points lambdock at a REPL socket inside the temporary directory.
The whole nested process group is killed (SIGTERM, then SIGKILL) on exit.

The terminals in the recording run a generated =lambdock-demo-shell= instead of
your shell (it is the =$SHELL= of the nested session only), so the frames show
deterministic, readable content instead of an empty prompt.

** Output geometry and cropping

The outer output is queried with =niri msg -j outputs=.  The nested output
(=winit=) uses a scale chosen from the physical width (2.0 / 1.5 / 1.0), the
nested window is fullscreened, and the capture is cropped *while recording*:

#+begin_src sh
wf-recorder -r 20 -D -F "crop=W:H:0:56,scale=1440:-2:flags=lanczos" -f raw.mkv
#+end_src

Only the top is cropped.  The dock lives on the bottom edge and a taskbar spans
the full width, so cutting the sides would clip the clock in taskbar mode; the
top margin is where the pointer rests before the storyboard starts, so the
cursor cannot enter the recording from there either.  The capture is 1440 px
wide and the GIF screen is 1100, so text is downsampled once, by the encoder,
rather than twice.

** Pointer control

=niri= supports =zwlr_virtual_pointer_manager_v1= but *not*
=wp_pointer_warp_v1=, so =vptr.c= is a ~150-line Wayland client that binds a
virtual pointer and exposes =move=, =glide=, =click=, =rightclick= and scroll
subcommands.

The pointer that drives the storyboard is bound to the *host* compositor, not to
the nested one.  A virtual pointer inside the nested session moves events but
not pointer focus: clicks land, but a hidden dock never sees the pointer reach
its reveal strip and the fish-eye never starts.  Driving the host pointer makes
the nested compositor see an ordinary pointer crossing its window, which is
exactly what a real user does.  Coordinates are translated with

#+begin_src python
factor = nested_scale / outer_scale
#+end_src

A virtual pointer does not move the host compositor's *cursor*, but niri draws
its cursor wherever the last pointer motion was, so the cursor that ends up in
the recording is the host's own -- the one a user would see.  The *nested*
compositor is given a fully transparent Xcursor theme
(=make_empty_cursor.py=) so it draws nothing: two cursors a few pixels apart was
exactly what the previous version of this recording had.

** Keeping the host cursor visible (temporary config edit)

The host compositor hides its cursor after a second of inactivity by default,
which would make the cursor blink out during every pause in a demo that is all
pauses.  The script therefore backs up the host niri config
(=~/.config/niri/config.kdl=, or =$NIRI_CONFIG=), sets
=hide-after-inactive-ms 3600000= in the existing =cursor { ... }= block, and lets
niri reload it for the duration of the recording.  The backup is restored
byte-for-byte on exit, including on failure (=trap ... EXIT INT TERM=).  This is
the only thing the recorder touches outside its temporary directory; pass
=--keep-cursor= to skip it (and expect the cursor to disappear between scenes).

** Timing

The recorder starts =wf-recorder= *before* it tells the controller to begin, and
waits for the capture file to actually grow (the log line that used to signal
readiness never appears in current wf-recorder builds, and waiting on it put ten
seconds of dead air in front of the storyboard, which made every caption early).
Video time zero is therefore within ~100 ms of event time zero.

The encoder cuts the tail at the last event plus 1.4 s, so a slow recorder
shutdown cannot add a frozen frame at the end of the GIF.

** Presentation

=make_overlay.py= produces the three inputs the encoder composites:

- =frame.png= -- a dark gradient backdrop with a soft two-layer shadow and a
  hairline border, drawn supersampled so the corners are clean;
- =mask.png= -- a greyscale rounded rectangle, one pixel smaller than the
  screen so the backdrop's border survives the overlay;
- =captions.ass= -- captions, theme labels and title cards, positioned in
  *canvas* coordinates so they never depend on the compositor's layout.

Captions are drawn as rounded pills (an ASS drawing command, since ASS has no
rounded rectangle primitive) at the top of the screen, because the dock owns
the bottom.  Theme labels appear top-right during the montage; the intro and
outro are dimmed title cards.  Everything fades in and out with a small rise.

** Encoding

Three passes, because feeding =palettegen= and =paletteuse= from one =split=
makes ffmpeg buffer the whole second branch -- an out-of-memory kill on a
recording this long:

1. composite the recording into the frame, caption it, write a lossless
   intermediate (=ffv1=);
2. build one global palette (=palettegen=max_colors=256:stats_mode=full=);
3. quantise (=paletteuse=dither=sierra2_4a:diff_mode=rectangle=) and optimise
   with =gifsicle -O3 --colors 256=.

The budget is 12 MiB; if the result is bigger, =gifsicle --lossy= is tried in
steps (20, 35, 50, 70), and the script suggests a smaller =--width= or =--fps=
if even that is not enough.  The palette is global on purpose: per-frame
palettes flicker on the static parts of the frame.

* Storyboard

The timeline is defined in =controller.py=; each phase logs =caption_start= /
=caption_end=, =theme= / =theme_end= or =title= / =title_end= events that become
the burnt-in text.

| Time | Scene | What it shows |
|------+-------+---------------|
| 0 s  | Title | wordmark and one-line summary over the dimmed desktop |
| 3 s  | Auto-hide | pointer to the bottom edge reveals the dock, leaving hides it; the settings file is then edited (=dock-auto-hide? #f=) and the dock returns and stays |
| 8 s  | Magnification | one slow pass across the row, icons growing under the pointer |
| 11 s | Launch | two clicks on the terminal launcher, two windows, running indicators |
| 15 s | Popover | right-click the running app, glide the window rows, *Close All* |
| 20 s | Menu + Preferences | right-click a separator, *Preferences...*, the dialog applied to the running dock |
| 29 s | Stack | the folder item opened as a thumbnail grid, browsed, dismissed |
| 33 s | Launchpad | opened over the REPL, filtered with =launchpad-search!=, closed |
| 40 s | REPL | a kitty terminal types real expressions: read the icon size, change it, then define a =swap!= helper |
| 47 s | Themes | eleven themes through =swap!=, wallpaper switching to the light one halfway; the two macOS Mavericks materials switch the dock to its 3D shelf geometry |
| 64 s | Taskbar | Windows XP taskbar mode |
| 72 s | Outro | windows closed, dock back to its default, closing title card |

Two rules that keep the recording honest:

- *Every caption describes something visible in its window.*  A scene that
  fails to open its window logs it and the run continues, but the frames are
  checked before the result is published (see below).
- *Popovers must be dismissed before the next scene.*  A popover grabs input,
  so a right click on the dock would be swallowed; each scene that opens one
  clicks the empty top of the screen to close it.

** Checking a recording before publishing it

Decode the GIF with something GIF-correct (=PIL=, not =ffmpeg=, which mis-renders
the frames gifsicle writes) and look at one frame per second: the dock must be
centred with both rounded ends visible, there must be exactly one cursor,
captions must not cover the UI they describe, and no scene may be empty.

* Calibrating the dock item coordinates
:PROPERTIES:
:CUSTOM_ID: calibrating-the-dock-item-coordinates
:END:

The storyboard addresses dock items by coordinate, and the item list comes from
the settings file the recorder generates.  Adding, removing or resizing an item
moves every item, so the numbers in =controller.py=
(=ITEM_ALACRITTY=, =ITEM_SEPARATOR=, ...) have to be re-measured.  Do it from a
recording rather than by eye:

#+begin_src sh
./tools/record-demo/measure_dock.py --raw /tmp/lambdock-demo.XXXX/raw.mkv --time 12
#+end_src

It prints the capsule and item centres in the same nested-logical coordinate
space the controller uses, ready to paste.  The reference layout (48 px icons,
eleven slots) looks like this:

#+begin_src python
ITEM_ALACRITTY = 251   ITEM_CHROME = 315      ITEM_NAUTILUS = 379
ITEM_CALCULATOR = 443  ITEM_SEPARATOR = 490   ITEM_EMACS = 535
ITEM_STACK = 600       ITEM_SEPARATOR_2 = 650 ITEM_RAM = 702
ITEM_CPU = 762         DOCK_ROW = 708
#+end_src

The Y coordinates are absolute too: =DOCK_ROW= is the item row, and the
popover's last row (=Close All=) sits at a fixed offset above the dock, so it
does not move with the number of windows.

* Reproducibility notes

- Wallpapers and all storyboard timings are deterministic; the only source of
  variation is compositor timing.  If a click lands during an animation, bump
  the preceding =sleep= in =controller.py= (the storyboard is written with
  generous holds).
- Wallpapers are generated at the *physical* output size and drawn with
  =-m fill=; keep their gradients low-frequency, because high-frequency detail
  (the first version had jagged mountain ridges) aliases into moire after the
  downscale and the 256-colour pass.
- Do not switch =wf-recorder= to a realtime codec: VP9 shimmering at low CRF
  inflated the GIF past 100 MB.  The lossless utvideo default is both cheaper to
  encode and cleaner after palette reduction.
- =wf-recorder= is started with =-D= (no damage tracking), otherwise static
  frames (the closing title card) are dropped from the raw video.
- The Guile thread hazard described in
  [[file:../../HACKING.org::#repl-guile-thread-hazard][the Guile thread hazard]] can still abort a long recording when many
  reloads run in a few seconds.  The demo's validated accessors and poller guard
  reduce it; if a run dies near the end, bump the holds in the theme montage.
