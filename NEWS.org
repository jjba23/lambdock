*[Released]*

** v0.21.0 (2026-10-31)
- *The honest-TODO list is empty.* HACKING has carried a "known rough edges"
  table for a while; every row on it is now off, and each fix moved a rule rather
  than a line count:
  - The meter's geometry is a value (~LambdockMeterGeometry~ +
    ~lambdock_meter_geometry_compute()~), with the green/amber/red thresholds
    behind ~lambdock_meter_tone_for_fraction()~; the snapshot function only draws
    what they describe, and both are unit tested.
  - The shelf's *value* types moved to =core/shelf_params.h=, so
    =core/dock_dims.h= and =core/config_values.h= no longer include the whole
    application header or a widget header -- the pure layer is now pure in its
    headers too. =lambdock.h= stopped including =libguile.h= as well: the only
    SCM value in it is a poll handle, and that is opaque now.
  - The desktop-entry cache is one ~DesktopEntryCache~ value instead of three
    file statics.
  - The icon search paths are built from explicit inputs
    (~lambdock_icon_search_paths_build()~) and then applied, so "system dirs,
    then the user's own, only if they exist" is a tested rule.
  - ~main.c~ and the preferences window use ~dock_registry_foreach()~ instead of
    hand-rolled snapshot loops, and the process-wide reload timer has one owner.
  - The window model moved out of =ui/dock_item.c=: tracking, running/focused/
    minimized styling and the app-id lookup are =ui/dock_item_windows.c= now, and
    pollers go through the bridge (~lambdock_poll_fn_protect/call/release~ and a
    plain ~LambdockReading~), so no =scm_*~ call lives outside =guile_bridge.c=.
  Old names, entry points and behaviour are unchanged: this is the round where the
  tree is taken all the way, not a round of features.

- *Stacks became a small file browser.* The stack panel used to be a printout of
  one folder: every entry -- folder or file -- went to the desktop. Now clicking
  a folder walks into it inside the panel, the header is a breadcrumb
  ("Downloads / Shots / 2024") with a back button while you are inside, a
  grid/list toggle that persists where the context-menu one does, and an
  *Open folder* button that hands the folder you are looking at to your file
  manager. A folder with more than the 300 entries the panel lists now says so
  ("300+ items", plus a line explaining the cut) instead of quietly ending.
  `lambdock_stack_list_directory_limited()`, `lambdock_stack_child_path()`,
  `lambdock_stack_parent_path()` and `lambdock_stack_breadcrumb()` are the pure
  pieces that make the browsing testable without a display, and the panel itself
  is built by the exported `lambdock_stack_panel_new()`.
- *The window menu grew icons, a focus mark and a keyboard.* Every entry of the
  context menu and the multi-window HUD now leads with a symbolic icon (a window
  for a new instance, a concealed eye for a private window, playback glyphs for
  the MPRIS controls, a bin for removals, the trash and folder icons where they
  belong), the view switch shows a check on the active view instead of a bullet
  character inside its label, and the list of windows marks the one that holds
  the focus with a dot, dims the ones the compositor reported as minimized, and
  keeps the close button quiet until the row is hovered or focused. The icon-only
  close button is now named for a screen reader ("Close window", with the window
  title as its description). The menu is also a keyboard object: it opens with
  the focus on its first row, Up/Down walk the rows, Home/End jump to the ends,
  and Escape closes it -- and the same controller stays inert on the stack panel,
  which handles its own arrow keys.
- *Both panels got a stylesheet.* The stack panel had no styling of its own
  (its tiles and rows were whatever the theme's generic `popover button.flat`
  rule made of them) and menu rows had none at all. A theme-agnostic block in
  `overlays.css` now gives menu rows their alignment and hover, the stack header
  its buttons, the grid tiles a card look with rounded thumbnails, the list rows
  a file-manager hairline, and the truncation note its place -- all expressed in
  `alpha(currentColor, ...)` so the light and the dark materials both work. The
  selectors are anchored on the panel's own container rather than on the popover
  element, which is also what lets them out-specify the themes' rules (GTK CSS
  has no `!important`), so a theme can still say what a panel *looks* like
  without losing what it *is*.

*[Released]*

** v0.20.0 (2026-10-31)
- *The launchpad lost its title, and its close button can move.* The overlay no
  longer writes "Applications" across the top: the grid of everything installed
  is the screen, and the search field says what it searches, so the header is now
  one close button. That button sits on the *left* by default -- where a
  window's own controls are -- and a new setting, ~dock-launchpad-close-side~
  (~'left~ or ~'right~), moves it to the other end. It is in the launchpad
  options table, in the options reference, in the Preferences window and in
  ~(configure-dock! #:launchpad-close-side 'right)~, and the layout is
  re-applied on every show, so the window does not have to be recreated to move
  it.
- *Add a widget to the dock from the Preferences window.* A new *Dock items*
  card offers one row: pick Trash, Clock, RAM usage, CPU usage, CPU temperature
  or Battery, press *Add*, and the item appears on the dock. It is stored as a
  ~"preset"~ entry in the dock's layout override -- the same file drag and drop
  writes -- so it survives a restart, can be dragged along the dock, and a
  right-click removes it like any other item; adding the same widget twice keeps
  one of it. The Scheme side picked this up as a general mechanism: a layout
  descriptor of kind ~"preset"~ replays ~(preset-launcher 'NAME)~, and its key is
  the key of the item it builds, which is what makes reordering and removal work
  unchanged. The trash can also joined the preset zoo, so ~'trash~ can be used
  like ~'ram~ or ~'clock~ in a settings file.
- *Every theme, state by state.* A theme can style more than the capsule: the
  hover and pressed states, the running indicator (~running-app~), the *focused*
  window (~window-focused~), the minimized dimming (~window-minimized~) and the
  running window's title (~window-title-label~). That set was audited across all
  nineteen themes and filled in where it was missing: Windows 10 now draws the
  long accent underline for the focused window and Windows 11 the wide pill (both
  had a single running indicator before), and the nine themes that never coloured
  the window-title label now do -- which is what made titles invisible on the
  light slabs. Two fidelity fixes came out of the same pass: the light macOS
  docks (Tiger, Snow Leopard, Mavericks) get a **dark** running dot and dark
  labels, because a white glow vanishes into pale glass, while their dark
  siblings, Big Sur, Ventura and Tahoe keep the white one; and the dot the glass
  shelf paints itself (C side) now sits on a soft shadow, so the white bead also
  reads on the platinum and Aqua slabs without changing how it looks on dark
  glass. The five stock themes (vanilla, vanilla-light, solarized-light, nature,
  unity) widen and brighten their glow pill for the focused window, so every look
  says which app you are in.
- *Scoping no longer loses a selector.* =theme_scope_css_selectors()= walks CSS
  line by line, and a selector list written across two lines
  (=button.window-focused,= / =:hover {=) had its first selector passed through
  *unscoped* -- so it applied to every dock and to the rest of the application.
  That is how one theme's indicator ended up painted under another theme's icons,
  and it was latent in =shelf.css= and =windows-xp.css= before this release. The
  scoper now accumulates the selector text until the block opens, and three unit
  tests cover multi-line lists (including one that starts with =window=).
- *A look carries the manners, not just the numbers.* The recipes now set
  ~hover-animate?~ too: the OS X docks magnify the icons under the pointer and
  every look descended from them turns the fisheye on, while the five Windows
  taskbars and the plain taskbar lay it off, because no Windows taskbar ever
  magnified anything. ~(apply-look! 'windows-11)~ therefore turns the fisheye off
  and ~(apply-look! 'osx-tahoe)~ turns it back on.
- *Looks: a whole dock in one line.* A theme gives the dock its material, but a
  dock is also a set of numbers -- icon size, spacing, end padding, dock or
  taskbar, and the eight glass-shelf parameters. Those numbers belong together,
  and they now do: =scheme/lambdock/looks.scm= ships twenty complete recipes,
  one per shipped theme, from Tiger's flat Aqua strip and Snow Leopard's 3D
  shelf to Mavericks (light and dark), Tahoe's Liquid Glass and the five Windows
  taskbars (XP, Vista, 7, 10, 11). A settings file says
  ~(define dock-look 'osx-mavericks-dark)~ and gets the dock of that desktop;
  anything it defines itself still wins over the
  recipe, and so do the choices made in the Preferences window. Short names and
  theme names are aliases (~'mavericks~, ~'tahoe-dark~, ~'xp~, ~'aero~,
  ~'seven~, ~'taskbar~), an unknown name is a warning instead of a broken
  config, and ~(apply-look! 'osx-snow-leopard)~ applies one to the running dock.
  Every
  recipe writes *all* of its numbers, including the ones that happen to be the
  defaults, so cycling through the looks never inherits a geometry from the look
  before it. Each recipe is unit tested for completeness and range, and so is the
  loader's "the file wins over the recipe" order.
- *Five Windows themes, one consistent family.* Windows Vista (~'windows-vista~,
  Aero glass: a near-black bar that is almost transparent at the top under one
  very bright specular line, glass task buttons that stay invisible until hover
  or a running window, and a lit -- rather than depressed -- focused tile) and
  Windows 7 (~'windows-7~, the Aero superbar: taller, bluer, darker, a thinner
  specular line, and buttons with square shoulders and rounded feet) join XP, 10
  and 11 in the bundle, the Preferences dropdown and the look recipes. The five
  Windows looks now share everything that can be shared -- all ~'taskbar~, all
  32px icons, all flat (no shelf geometry) -- and differ only where the era did:
  window titles are on for XP and Vista and off for 7, 10 and 11, and the gaps
  run from XP's edge-to-edge Luna buttons (~0~ spacing, ~4~ of end padding) to
  Windows 11's airy rounded tile (~8~, ~12~). A test asserts the whole family
  stays that way.
- *Three more themes, and a shelf for the two that missed it.* macOS Tiger
  (~'macos-tiger~) is the dock before the 3D shelf: a flat, pale Aqua strip the
  icons sit *inside*, with a bright bevel along the icons' edge and a cool grey
  lip on the screen side. macOS Tahoe (~'macos-tahoe~, ~'macos-tahoe-dark~) is
  the 26 *Liquid Glass* pill -- rounder and thinner than Ventura, one bright rim,
  no mirrors. Snow Leopard's themes (~'snow-leopard~, ~'snow-leopard-dark~) can
  now wear the 3D shelf properly: they carry the slab material the generic
  =shelf.css= used to impose on them, in pale glass and in smoked glass. All
  three new themes are in the Preferences dropdown, in the GResource bundle and
  documented with their numbers.
- *The README documents the recipes.* A new [[#looks][Looks]] section tabulates
  every recipe (theme, icons, spacing, end padding, overhang, front glass,
  keystone and mirror band) and explains what those numbers buy, with the
  measurements the OS X ones came from.

*[Released]*

** v0.19.5 (2026-10-29)
- *Measured, not guessed: the dock's share of a hover frame.* A new =hover_us=
  counter accumulates the time spent in the dock's own hover path, and the budget
  test prints it per frame. On a row of eight items one hover frame costs about
  30 us of the dock's work -- 0.2 % of a 16.7 ms frame -- and on a running
  27-item dock the whole process reads 0 jiffies in ten seconds while idle and 0
  while hidden, and about 7 % of one core during a four-second hover sweep. The
  magnification's arithmetic is therefore not what costs anything; the rest is GTK
  measuring, allocating and painting the row, which is what magnifying a row of
  icons is, and the one lever left (a coarser =FISHEYE_LAYOUT_STEP_PX=) would buy
  it back with visible pops in the mirrors. The test now asserts the per-frame
  ceiling so a regression shows up as a number.
- *Edge behaviour audited with a pointer, not by eye.* Nothing is clipped at the
  ends of the row (the applied input region stays at least 25 px inside the
  surface on both sides), the row widens without jumping vertically (neighbours
  keep their bottom edge while the item under the pointer grows), and the screen
  edge does not bounce: twelve crossings in and out of the dock in two seconds
  give twelve leave/enter pairs and zero hides, a real leave still hides it
  exactly once, and twelve jitters along the trigger strip give exactly one
  reveal.
- Input-region applications are now counted too: one every two or three hover
  frames, not one per frame.

*[Released]*

** v0.19.4 (2026-10-29)
- *Auto-hide: the dock comes back.* A tucked-away dock is on screen only as the
  trigger strip, and that strip is only reachable because the whole surface is
  given back its input region while the dock is away. That region was being set
  but never *committed*: Wayland surface state is double buffered, and a dock
  that has finished sliding draws nothing, so the new region sat in the queue
  while the compositor kept the old, dock-shaped one. Intersected with the four
  pixels that are still on screen, that is nothing at all -- the strip was dead.
  It worked intermittently, whenever something else happened to draw a frame, or
  whenever the slide committed one after the region was set. One
  =gtk_widget_queue_draw()= after applying the region is the fix, and three
  hide/reveal cycles in a row now behave identically.
- *Auto-hide: a pointer that never moved still has to be able to reveal.* A
  pointer that rests on the strip while the surface slides away under it never
  crosses back into the dock: the compositor keeps sending it motion, not a
  crossing. Waiting for an enter stranded the dock off screen for as long as the
  pointer stayed at the screen edge -- which is where a pointer that just used
  the dock tends to be. Motion inside the surface while the dock is away now
  means the same thing an enter does.
- *Auto-hide: a reveal can no longer lose a race with the hide it is
  cancelling.* A reveal that arrives while a hide has been requested but has not
  had its first frame yet used to be dropped ("already at margin 0"), and the
  hide went on: the dock ended up off screen while believing it was visible,
  where nothing could bring it back. A slide in flight toward a different target
  is now turned around instead of ignored.
- *Auto-hide: a leave only counts as an echo while the dock is actually
  moving.* It also used to require that the pointer had moved since it entered,
  which threw away genuine leaves -- touch the edge to reveal the dock, then move
  away without moving *over* it, and the dock stayed out. The settle window
  alone is what tells an echo apart, and it is what is used now.
- *Auto-hide: the trigger strip is 4 px instead of 2.* Two pixels is one pixel
  at 2x scale and less at the dock's usual 1.2x, and a pointer that stops a hair
  short gets nothing. It is the top of the shelf's magnification headroom, so it
  still shows nothing, and half a text line is all it costs.
- =LAMBDOCK_DEBUG=1= now traces the whole auto-hide sequence -- crossings, the
  hide margin that was computed, the input region that was applied, and every
  slide -- with timestamps. The interesting failures happen on somebody else's
  compositor, and "it hides but does not reveal" is a report about a sequence,
  not about a value.
- The dock's row is measured to magnify *monotonically* now: a straight sweep of
  the pointer over the row may grow an icon and shrink it, and not oscillate,
  which is the difference between magnification and a wobble (new /perf/ test).

*[Released]*

** v0.19.2 (2026-10-29)
- Auto-hide works again. v0.19.1 cut the surface's input region down to the dock
  to stop the room it reserves from eating clicks -- but a tucked-away dock is
  only on screen as the trigger strip at the screen edge, and that strip is the
  surface's *headroom*, exactly what the region had just cut away. With nothing
  to enter, the pointer could never bring the dock back. While the dock is hidden
  or sliding the whole surface now takes input (the off-screen part cannot be
  clicked anyway); once it is out and settled the region is the slab plus the row
  of icons again, and it is only re-set when it actually changes, so a slide no
  longer touches the surface's input state on every frame.
- The hover path is measured, and the measurements are tests. =render_stats.c=
  keeps integer counters for the work a frame does -- frames applied, frames
  dropped, item layout steps, geometry-cache rebuilds, icon and reflection paints,
  surface resizes -- and =test_render_budget.c= drives the real hover path against
  a hand-allocated row (no window, no compositor) to assert the budget: over 40
  frames sweeping eight items, 91 layout steps (of 320 possible), 31 geometry
  rebuilds (fewer than there are frames) and *zero* surface resizes.
- Hover geometry is cached. Each item's centre along the dock axis is measured
  once per layout change and reused, so a pointer frame costs arithmetic instead
  of a transform query per item; the cache is invalidated by the one function that
  changes geometry, and by items appearing or disappearing.
- Sub-pixel pointer movement is dropped before it touches a widget: a trackpad
  reports fractions of a pixel continuously, and half a pixel cannot change what
  is painted. Twenty jitter frames now cost zero layout steps and zero geometry
  rebuilds.
- The reflection fade's cost is a number instead of a guess:
  =lambdock_reflection_band_count()= is pure, unit tested, and documents that one
  reflection repaint costs 14 clipped draws at the 14 px band the macOS Mavericks
  shelf uses (16 at worst).
- =HACKING.org= documents the widget tree, the three clocks (layout, animation,
  data) and the measured per-frame budget.

*[Released]*

** v0.19.1 (2026-10-29)
- Hovering the dock no longer resizes it, which is what made it flicker and
  tear along its edges. The fish-eye grows the icons, and growing widgets inside
  a window makes GTK resize the window: on Wayland that is a buffer
  re-allocation and a compositor reconfigure on *every* pointer frame. The room
  the row can spread into is now reserved once, before the pointer starts
  magnifying, so the surface keeps its size for the whole hover; a dock that was
  sweeping the pointer across a long row was reconfiguring its surface dozens of
  times a second, and now it does it once when the pointer arrives.
- The room the dock reserves -- including the headroom above the capsule that was
  always there -- is no longer part of what it listens to. The surface's input
  region is cut down to the capsule plus the row of icons (the bounds are recomputed
  when the dock is mapped, when its geometry changes, and while it magnifies), so
  the invisible band around the dock cannot swallow a click meant for the window
  underneath. Before this, the transparent area above the dock was a dead zone.
- The icon-zoom test no longer snapshots a widget between a resize and its
  allocation, which is a GTK warning and a flaky test on a loaded machine.

** v0.19.0 (2026-10-29)
- The clock item is an analogue face instead of a time string. It is drawn from
  geometry -- no artwork at any size -- as a squircle body with a brushed bezel,
  a paper dial shaded from the top-left, twelve hour ticks and sixty minute
  ticks, an hour, minute and second hand, and one sweep of glass across the body:
  a watch face is an object, so it keeps its own colours rather than following
  the theme, and it takes exactly one icon cell instead of pushing a string's
  worth of width into the row. The poll function keeps its job -- the string it
  returns is the face's tooltip and what a screen reader announces -- while the
  hands are read from the system clock, so the dock shows the right time even
  when its own timer was skipped while it was hidden.
- The face's geometry (where each hand points, and where a squircle runs) is a
  pure function with its own test, because an hour hand on the wrong minute is
  the kind of bug nobody notices until it is three o'clock.
- The showcase recording and its stills are re-recorded, and the recorder's item
  coordinates are re-measured: a face is a cell narrower than the string it
  replaced, and the dock is centred, so every item before it moved.

** v0.18.0 (2026-10-29)
- The showcase recording is now a two-stage pipeline -- =record-demo.sh= records,
  =encode-demo.sh= frames and encodes -- and the GIF it produces is presented
  instead of merely captured: the screen sits inset in a dark backdrop with a
  rounded, shadowed edge, captions arrived as rounded pills at the top of the
  screen, theme names get their own label, and the intro and outro are dimmed
  title cards.  The whole presentation layer (=tools/record-demo/make_overlay.py=)
  works in output coordinates, so it does not depend on the compositor's layout.
  A 72-second version of the previous storyboard was 15 MiB; the new ~60-second
  one fits the same budget with more of the frame in use.
- The pointer that drives the demo now belongs to the *host* compositor.  A
  virtual pointer inside the nested session delivers clicks but does not move
  pointer focus, so a hidden dock never saw the pointer reach its reveal strip
  and the fish-eye never started -- two headline features could not be filmed at
  all.  Driving the host pointer makes the nested compositor see an ordinary
  pointer crossing its window, and because a virtual pointer does not move the
  host's hardware cursor, the recording contains exactly one cursor: the real one
  the compositor draws.  The cursor the old encoder painted in post (which
  drifted out of sync because its ~\move~ used absolute timestamps) is gone.
- The storyboard was rewritten rather than retimed: twelve scenes, each about
  four seconds, each one checked frame by frame against its caption.  The window
  popover, the dock's own menu and the Preferences window are now actually shown
  (their click targets were calibrated against an older layout and had been
  missing their marks, so one scene opened the wrong menu and removed a dock
  item).  The demo terminals run a generated demo shell and show a system
  summary and a file listing instead of an empty prompt, and closing the REPL
  terminal no longer leaves kitty's "are you sure?" dialog on screen for the
  last ten seconds.
- Recording and event time are now in sync.  The recorder used to wait for a log
  line current =wf-recorder= builds never print, so it always waited its full
  timeout and started capturing ten seconds early: every caption landed ten
  seconds before the thing it described.  It now waits for the capture file to
  grow, and the encoder trims the tail at the last event, so a slow recorder
  shutdown cannot add dead air either.
- The capture is cropped only at the top, at 1440 px, and downsampled once by
  the encoder: nothing of the dock is cut (a taskbar spans the whole width) and
  text stays crisp after the palette pass.  The generated wallpapers
  were rebuilt as low-frequency gradients -- the old jagged mountain ridges and
  dense star field aliased into visible moire once the GIF was downscaled -- and
  the light one is now a soft haze instead of hard-edged polygons.
- The recorder no longer draws its own cursor and no longer needs a checklist of
  coordinates in the docs: =tools/record-demo/measure_dock.py= measures the dock's
  capsule and item centres in a recording and prints them ready to paste.  That
  is how the storyboard's table was rebuilt, and the tool is the answer to
  "adding an item moved everything".
- Fixing the run also exposed a real dock bug: while an icon is magnified the
  capsule keeps its resting width, so the row overflows and the clock is clipped
  mid-glyph.  It is visible in every hover frame of the old GIF.  (Tracked, not
  fixed here.)
- The launchpad search field takes the keyboard the moment the launchpad opens:

- One dock implementation described by plain numbers -- no modes, no presets:
  `dock-shelf-tilt`, `dock-shelf-perspective`, `dock-shelf-margin`,
  `dock-shelf-front`, `dock-reflection`, `dock-reflection-intensity` and
  `dock-reflection-blur`. All default to the classic flat capsule.
- `dock-shelf-margin` accepts negative values, which is how the OS X dock lets
  its icons overhang the shelf; `dock-shelf-front` is the glass (front face) in
  front of them.
- Icon reflections now fade over the front face, with a soft contact shadow
  under each icon and the white running-app glow dot near the outer edge
- New light frosted `css/shelf.css` modifier plus a rewritten `'macos-mavericks`
  theme (platinum slab, specular outer edge, bluish thickness band)
- Add `ui/shelf.c` (`LambdockShelfFrame` + `LambdockReflection`) with a unit
  test suite covering the derived geometry
